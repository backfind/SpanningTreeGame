# 伸展树 8×8 联机对战

基于原单机版 `run.html` 的规则实现的在线双人对战，**服务端权威逻辑**，客户端只负责渲染与发操作。

## 本地运行

```
node server.js
```

打开 http://localhost:3000 ，一人「创建房间」得到房间号，另一人输入房间号「加入房间」。第三人是观战。支持 `?room=房间号` 直达。

## 零依赖设计（Render 免费版兼容）

- 纯 Node 内置模块（`http`），无 npm 依赖、无构建步骤。
- 状态同步用 **SSE**（`GET /api/events?room=`）+ 心跳注释防代理超时；操作用 `POST /api/action`。
- Render 免费档无需 GPU，此项目只用 CPU/内存，0.1 GPU 完全够用（实际用不到 GPU）。

## Render 部署

1. 仓库推到 GitHub，Render 控制台 **New → Web Service** 连接仓库。
2. Runtime 选 **Node**；Build Command 留空；Start Command：`node server.js`。
3. 实例类型选 **Free**。Render 自动注入 `PORT` 环境变量，`server.js` 已适配。
4. 免费实例 15 分钟无流量会休眠，休眠后**内存房间清空**，对局需重开；可挂外部监控保活（可选）。

## 架构

| 文件 | 说明 |
| --- | --- |
| `server.js` | 房间管理、全部规则校验与状态机、SSE 推送、静态页 |
| `public/index.html` | 棋盘渲染（SVG 边线/冻结纹理）、操作交互、大厅 |
| `run.html` | 原单机版（保留，未改动） |

## 相对原版的规则修正

按此前审查结论，服务端实现修正了三处原版偏差：

1. **冻结点可作嫁接 y**（原版漏检）→ 现已拒绝。
2. **源点作嫁接 x 时颜色校验缺失** → 现校验 x 实际颜色 ≠ y 颜色。
3. **交叉删除漏嫁接边** → 与对方斜边交叉时，普通边和嫁接边都会被删除。

其余规则与原版一致：归属仅由普通边连通决定；每回合 1 次嫁接 + 至多 3 次伸展（可提前结束）；同回合伸展颜色不重复；越界/无主点清理；杀点冻结其邻点；源点被毁判负。
